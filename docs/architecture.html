How the forest bot works

Animals send advice as files and ask questions as text. The bot answers only from those documents and the preloaded «Лісовий архів», and every answer ends with a citation the code builds itself.

7 · Startup

What python -m bot.main does, in order

  1. Settings() reads .env. No token means a validation error and no start.
  2. Create engine and tables. Compose waits for the db healthcheck first.
  3. import_archive reads manifest.json. Each entry has a scope chosen by reading the document; titles alone mislead.
  4. Skip files whose hash is already stored. Restarts are fast, and archive docs an animal replaced stay replaced.
  5. Build the Dispatcher with session_factory and ChatMemory. aiogram injects them into handlers by parameter name.
  6. Register the error handler, then start_polling. Unexpected bugs are logged and the animal gets «Ой, щось пішло не так».
8 · For the interview

Decisions and the reason behind each

AsyncGroq, one client per process

LLM calls are I/O-bound, so awaiting them keeps the event loop free for other animals. One client reuses its HTTPS connection pool instead of a TLS handshake per message.

OCR in asyncio.to_thread

OCR is CPU-bound. await alone does not help there; a thread keeps the bot responsive while a scan is read.

Citations built by code

The model only returns the number of the one document it used. Code formats «з документа …, надіслав …, дата» so the format always matches what the client approved.

Hybrid retrieval, no vectors

Groq has no embeddings model. The router model matches by meaning on titles, BM25 matches words in the text, and the two lists are merged.

Two model sizes

gpt-oss-20b for routing and classifying, gpt-oss-120b for answers. Each model has its own free-tier rate limit, and the small one is faster.

Scope filter in code, not the LLM

The client said never guess the place. Regexes over a fixed list of 8 places are exact and fully covered by tests.

Prompt-injection guard

Uploaded text goes into the answer prompt, so a file that gives orders to the bot is rejected at upload, on top of the prompt's own rules.

Replace, don't delete

Versioning flips is_active and links replaced_by_id. Answers stay current, and history stays for debugging.

Database not exposed

No ports on the db service: only the bot container can reach it on the Compose network.

uv sync --locked, multi-stage, non-root

The image installs exactly what uv.lock says, ships without uv or build cache, and runs as an unprivileged user.
